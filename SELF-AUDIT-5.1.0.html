一、实测发现与修复

缺陷根因修复
🔴 凭据窃取只判 MEDIUM
第一卖点形同虚设		 「引号内降级」规则本是给 .md 文档正文设计的，却套用到了 .py 上。而代码里的路径本就写在引号内，于是 P0 被降成 P1、语境被标成「文档提及」。 新增 _sink_string_lines()：用 AST 判断字符串是否被 open/system/read_text 等危险 sink 真正使用。被真正使用 → 不降级；仅文案字面量 → 降级不误报。
🔴 discover --new 崩溃 registry 用 '2026-03-05' 字符串、缓存用毫秒整数，排序时直接取负 → TypeError。 新增 _ts() 统一归一为秒级时间戳，无法解析返回 0。
🔴 quality 评不了自己
出场必演示项穿帮		 discover_local() 无条件排除自身目录名。 增加 include_self 参数；quality 支持 self/slug/别名；默认仍排除自己（搜索结果不自荐）。
🟡 文档数字自相矛盾 子命令数同时出现 14 / 16（实际 17）；增强项 45 与 37 打架。 全面对齐为 17 个子命令 / 49 项增强，并由冒烟脚本持续校验。

二、检测力对照（修复前 → 修复后）

样本修复前修复后说明
print(open('/root/.ssh/id_rsa').read())MEDIUMEXTREME真实窃取，禁止安装

exec(base64.b64decode(...))EXTREMEEXTREME保持
推广文案 "能识破偷读 ~/.ssh 的行为"MEDIUM降级，不误报关键：文案提到 ≠ 真的读
.md 正文「不要泄露 ~/.ssh/id_rsa」MEDIUM保持宽容文档警示写法
print('hello world')LOWLOW干净样本不误报
为什么这是「AST 级」而不是正则玩具：判据不是「命中就拉满」，而是字符串是否真的被用于危险调用。 纯正则无法区分 open('~/.ssh/id_rsa') 与 print("小心 ~/.ssh")——前者是窃取，后者是文案。

三、新增：端到端冒烟自证

单测只能证明函数对，证明不了「用户真的敲下去能跑」。新增 scripts/smoke.py：

python scripts/smoke.py
  • 真跑 17 个子命令的 --help、9 个只读子命令、7 组参数变体（含历史上崩过的）
  • 6 组恶意/干净样本验证检测力：5 组恶意须全判 EXTREME，干净样本须判 LOW
  • 文档数字一致性自检：SKILL.md 里写的子命令数、增强项数必须与实现一致
  • 任一项不过即 FAIL；--json 供 CI 消费，已接入 GitHub Actions
